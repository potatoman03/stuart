## Deck planning

### General principles

- Plan the slide sequence before writing bullets.
- Use section dividers for major transitions.
- Keep content slides to one main idea.
- Prefer comparison, table, and diagram slides when they teach better than bullets.
- End with a summary slide, optionally followed by explicit sources / references.

### Slide count recommendations

| Presentation length | Recommended slides | Notes |
|---|---|---|
| Quick overview (5 min) | 6-8 | Cover + 4-5 content + summary |
| Standard talk (10-15 min) | 10-16 | Cover + TOC + 2-3 sections with 2-3 slides each + summary + sources |
| Full lecture (30-45 min) | 20-30 | Cover + TOC + 4-6 sections with 3-5 slides each + summary + sources |
| Workshop / deep dive (60+ min) | 30-50 | Cover + TOC + 6-8 sections, mix of content types, multiple summaries |

Aim for roughly 1 slide per 1-2 minutes of speaking time. Dense data_viz or diagram slides may take longer; budget 2-3 minutes each.

### Visual variety rules

- **Never use 3+ identical layouts in a row.** Alternate between text_heavy, comparison, table, diagram, and timeline slides.
- After every 3-4 content slides, insert a section_divider or a different content subtype to break visual monotony.
- Pair dense text slides with a visual slide immediately before or after.
- Use timeline slides for processes and sequences rather than long bullet lists.
- Use comparison slides instead of listing pros/cons in separate bullet slides.

### Content density per slide type

| Slide type | Max bullets / items | Notes |
|---|---|---|
| cover | 0 (title + subtitle only) | Keep clean and dramatic |
| toc | 4-8 entries | One entry per major section |
| section_divider | 0 (number + title only) | Breathing room for the audience |
| content (text_heavy) | 5-7 bullets | Each bullet should be one line |
| content (mixed_media) | 3-4 bullets + 1 visual | Text supports the visual, not the other way around |
| content (data_viz) | 1-2 bullets + table/chart | Let the data speak |
| content (comparison) | 3-4 items per column | Keep columns balanced in length |
| content (timeline) | 4-6 steps | Each step as a concise phrase |
| content (image_showcase) | 0-1 bullets + visual | Maximize visual impact |
| two_column | 3-5 items per column | Balance both sides |
| table | 3-6 rows, 2-4 columns | More than 6 rows becomes hard to read at slide distance |
| diagram | 1 visual + optional caption | Caption should be one sentence |
| summary | 3-5 takeaways | Crisp, memorable phrases |
| sources | All relevant sources | Group by type if many |

### Transition flow guidance

A well-structured deck follows a narrative arc:

1. **Opening** (cover, toc): Set context and expectations
2. **Build-up** (section_divider -> content slides): Introduce concepts progressively, from simple to complex
3. **Evidence** (data_viz, table, diagram): Support claims with structured evidence
4. **Synthesis** (comparison, two_column): Draw connections and contrasts
5. **Conclusion** (summary, sources): Crystallize key takeaways

#### Recommended transitions

- cover -> toc -> section_divider (always start this way for 8+ slide decks)
- section_divider -> text_heavy -> comparison or table (introduce then contrast)
- data_viz -> text_heavy (show data then explain implications)
- diagram -> text_heavy (show visual then unpack it)
- timeline -> summary (show progression then conclude)
- Any section's last slide -> section_divider (clean break before next topic)

#### Anti-patterns to avoid

- text_heavy -> text_heavy -> text_heavy (bullet fatigue)
- diagram -> diagram (visual overload without explanation)
- section_divider -> section_divider (empty transitions)
- cover -> content (skipping the roadmap)
- Ending on a content slide instead of summary
